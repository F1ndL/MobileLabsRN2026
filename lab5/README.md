# Лабораторна робота № 5

Тема: побудова навігації у React Native із використанням бібліотеки Expo Router.

## Інструкція запуску

1. Встановити залежності:

```bash
npm install
```

2. За потреби синхронізувати версії пакетів із поточним Expo SDK:

```bash
npx expo install --fix
```

3. Запустити застосунок:

```bash
npm start
```

Після запуску можна відкрити застосунок в Expo Go, Android Emulator, iOS Simulator або web-версії.

## Реалізований функціонал

- Налаштовано Expo Router із file-based маршрутизацією в директорії `app`.
- Створено глобальний `AuthContext` зі станом `isAuthenticated` та методами `login`, `register`, `logout`.
- Реалізовано публічну групу маршрутів `(auth)` з екранами входу та реєстрації.
- Реалізовано захищену групу маршрутів `(app)`, яка перенаправляє неавторизованого користувача на `/login`.
- На головному екрані відображено каталог товарів через `FlatList`.
- Для переходу до деталей товару використано `<Link asChild>`.
- Реалізовано динамічний маршрут `details/[id]` з отриманням параметра через `useLocalSearchParams`.
- Додано сторінку `+not-found` з повідомленням "Екран не знайдено" та переходом на головну.

## Висновки та відповіді на контрольні запитання

1. Перенаправлення неавторизованого користувача в Expo Router реалізується у `_layout.jsx` захищеної групи маршрутів. Якщо `isAuthenticated === false`, компонент повертає `<Redirect href="/login" />`, тому користувач автоматично потрапляє на екран входу.

2. `<Link>` використовується як декларативний компонент переходу в JSX, наприклад для кнопок або карток товарів. `router.push()` використовується імперативно всередині функцій, наприклад після успішного входу або натискання кнопки.

3. Динамічні маршрути створюються файлами із параметрами в квадратних дужках, наприклад `details/[id].jsx`. Значення параметра отримується через хук `useLocalSearchParams()`, після чого за `id` можна знайти потрібний товар.

4. Стан авторизації доцільно зберігати у глобальному React Context, тому що він потрібен різним екранам і layout-компонентам. Локальний стан окремого екрана втрачався б при переходах і не дозволяв би централізовано захищати маршрути.

5. Групи маршрутів, наприклад `(auth)` і `(app)`, використовуються для логічного розділення екранів та застосування окремих layout-компонентів. Назва групи не потрапляє в URL, тому `app/(auth)/login.jsx` відкривається як `/login`.
